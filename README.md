# 前台 · 单体酒店前台管理系统

面向单体酒店（30–100 间房）前台的单页应用：手机优先、桌面自适应，**同一套代码**。
纯前端、无后端，数据全部保存在浏览器 localStorage 中，可添加到手机桌面（PWA）。
视觉方向「石与灯 / Stone &amp; Lamp」——纸白、墨黑、一盏琥珀灯。

## 技术栈

- Vite 5 + React 18 + TypeScript（strict）
- 无任何后端、无外网 CDN：字体使用系统字体栈，图标为内联 SVG，图表自绘 SVG
- 状态持久化：单个 localStorage key（`hotel-pms.state.v1`），带版本号与归一化迁移
- PWA：`public/manifest.webmanifest` + 轻量 Service Worker（离线可打开，仅生产构建注册）

## 快速开始

```bash
pnpm install     # 或 npm install
pnpm dev         # 开发服务器 http://localhost:5173
pnpm build       # 类型检查 + 构建，产物在 dist/
pnpm preview     # 本地预览构建产物 http://localhost:4173
```

要求 Node ≥ 18。首次运行 `pnpm install` 若提示 esbuild 构建脚本未执行，执行 `pnpm approve-builds`
允许 `esbuild` 即可（已在 package.json 中声明 `pnpm.onlyBuiltDependencies`）。

## 部署

构建产物使用相对路径（`base: './'`），可直接丢到任意静态服务器，包括子目录部署：

```bash
pnpm build
# 把 dist/ 整个目录上传到服务器，例如：
#   nginx: root /var/www/hotel/;  →  https://example.com/hotel/
#   python -m http.server --directory dist 8080
```

注意事项：

- 必须用 HTTPS（或 localhost）才能安装 PWA 与 Service Worker。
- 因为是纯前端，多台设备之间的数据**不会自动同步**，请用「导出 / 导入 JSON」人工搬移。
- Service Worker 缓存了应用外壳，发布新版本后刷新一次即可拿到新资源（导航请求为网络优先）。

## 关键业务口径

- **房态 7 态**：预订占房 / 空净 / 住净 / 空脏 / 住脏 / 当日预离 / 维修停售。
  存储只有 `status(vacant|occupied|reserved|ooo)` + `clean(clean|dirty)`；
  **当日预离是派生状态**：在住订单的预离日 == 当前营业日。
- **营业日**：从当天 `nightAuditHour`（默认 06:00）到次日同一时刻。所有“今日”统计与预离判定
  都按营业日，不是自然日。夜审时间在「更多 · 设置」可改。
- **押金不计营收**：停车费与其他费用单列为「其他费用」，
  **总收入 = 房费 + 其他费用**；押金单独放在灰底区块并带锁图标。
- **营收按间夜分摊**：住 3 晚 ¥600，每天营业日各记 ¥200 房费；
  停车费 / 其他费用整笔记在入住当天营业日。
- **续住是动作不是状态**：改预离日期 + 加收房费。
- **交接班**不记录金额、不需要双方确认，只记班次、交班人、接班人、时间、待办、备注。
- 房间数量上限 100 间；房号、房型、房价、渠道均可自由增删改。

## 数据备份与恢复

| 操作 | 位置 | 说明 |
| --- | --- | --- |
| 导出 JSON | 更多 · 数据备份 / 顶栏下载图标 / `Ctrl(⌘)+S` | 下载完整 state 快照文件 |
| 导入 JSON | 更多 · 数据备份 | 导入前自动写一份快照，并明示「将覆盖 X 间房 Y 条订单」，需确认 |
| 每日快照 | 自动 | 每天首次打开自动生成，保留最近 3 份，可一键回滚 |
| 撤销 | Toast「撤销」/ `Ctrl(⌘)+Z` | 中低风险操作保留撤销栈（最近 30 步） |
| 示例数据 | 引导页 / 更多 · 数据备份 | 12 间房 + 在住、预订与历史订单，用于立刻体验 |
| 清空 | 更多 · 数据备份 | 二次确认，5 秒内可撤销 |

> 数据仅存于本机浏览器。清理浏览器数据、更换设备或使用无痕窗口都会导致数据丢失，请定期导出备份。
> 首页顶部警示条会在「从未备份」或「超过 7 天未备份」时出现。

## 交互约定

- 房卡**单击**打开详情（只读信息 + 动作区），**不改变状态**；**长按 300ms**（桌面右键）弹出快捷动作菜单，
  按当前状态动态排序且不超过 5 项。**不使用滑动改状态**。
- 防误操作分级：
  - 高风险（退房结算、转维修、删除）→ 面板底部单行确认条，回显房号与金额，不用 Modal；
  - 中风险（入住、续住、置净、置脏）→ 直接执行 + 5 秒 Toast 撤销；
  - 低风险 → 无提示。
- 卖重房防护：入住 / 预订的房号选择器只放行「空净」房，其余灰显禁用；强行提交会阻断并说明原因。
- 房卡信息分级：卡面最多 4 块信息；**空房显示房价，在住房不显示房价**（防窥屏）；
  房价、押金、渠道、入住日、手机、费用明细、备注在详情面板中。
- 桌面（≥900px）增强：左侧导航 + 中间房态网格 + 右侧 360px 常驻详情面板；Hover 房卡出现快捷图标行。

## 已知限制

1. 单浏览器本地存储，无多端同步与多用户权限；如需多设备使用请靠导出 / 导入 JSON。
2. 撤销栈保存在内存中，刷新页面后不可撤销（持久化数据不受影响）。
3. 未实现房费按日不同价（每晚不同房价）、钟点房、联房与账单打印。
4. 已退房的订单按「预订晚数」分摊房费；提前退房按实际间夜计营收，但不做差价重算。
5. 趋势图为最近 30 个营业日，按天聚合，不支持自定义时间区间。
6. iOS 上添加到主屏幕后由系统管理存储，长期未使用可能被清理，请定期导出。
